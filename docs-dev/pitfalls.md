**#28（V3.4.3）首頁卡片在手機變空白方框 + TOC 太寬**

V3.4.2 部署後 Sela 反映兩件事（連同 TOC 縮窄一起做）：

1. **手機版首頁的 8 張快速導覽卡片變空白方框**——卡片框線在但裡面什麼都沒有（截圖證實）
   - 真因：`docs/index.md` 的 home-card 結構是
     ```html
     <div class="home-card" markdown>
     <a href="...">
     <svg .../>
     工作指導手冊</a>
     <p>新人必讀。日常...</p>
     </div>
     ```
     Markdown 渲染會把「圖示+標題+連結」那行**自動包進 `<p>`**（看 build 後的 site/index.html 的實際 DOM 證實）。V3.4.0 的 mobile CSS 寫 `.home-card p { display: none }` 想砍描述，結果連標題那個 `<p>` 也一起砍了

   - 做法：選擇器改 `.home-card > p:nth-of-type(2) { display: none }`，只砍第二個 `<p>`（描述），第一個 `<p>`（含 `<a>` + SVG + 標題）保留。`:nth-of-type` 是經典 CSS、所有手機瀏覽器都吃；不用 `:has()` 避免相容性風險

2. **右側 TOC 太寬，內文擠**——Material 預設 `.md-sidebar--secondary` 寬 12.1rem

   - 副作用：較長的 H3（如「Stage IV ≠ 一定轉移：細分亞期的癌別」、「健保給付 NGS 適用癌別」）在 TOC 內會折成兩行——可接受，仍可讀；不到 9rem 不會擠到全部標題折行
   - 跟規則 8 不衝突：規則 8 講的是「用 760px CSS 強迫 primary sidebar 在窄 viewport 顯示」（違背 Material 行為）。改 secondary sidebar width 是純樣式調整，性質完全不同

  2. 規則 6 第 1 道 grep 補 `Aborted`

  - **過濾 build 輸出時，要知道自己濾掉了什麼**——`grep WARNING|ERROR` 假設「重要的訊息一定含這兩個字」，那是**對工具的假設，不是事實**

**#77（本版）我違反了自己貢獻給 Kit 的 §7：一串裸 replace 沒 assert，其中一個因縮排不符靜默失敗——產出一個讓整支 UI JS 停掉的 ReferenceError，而四道煙霧測試全綠**

  - 🔑 **測試面板全綠 ≠ 沒問題，只等於「測試涵蓋的範圍沒問題」**——每次交付新的「層」（這次是 UI JS 行為層），要先問「**現有測試真的碰得到這一層嗎**」（Kit #78 的判準）。碰不到就補一道，不要靠人眼。

**#78（本版）Sela 說「我怎麼覺得版本號常常沒有跟上」——診斷出三層，主因是快取，而規則 1 的七處同步從頭到尾沒壞**

  3. **敘述層**：README「5 個一級分類（V4.20.1 現行）快速入口（**首頁 / 工作 / HIS / 指標**）」——**我 V4.20.1 的修正是半吊子 replace**：只換了字首、括號裡的舊 4 鈕清單沒動（審稿也抓到）；加上「17 份 MD」（實際 43 檔）、CLAUDE.md 檔案摘要「4 個 SVG 入口」。
  4. **內部同步層**：即時掃描七處 + 3 教材——**全部一致**。**規則 1 的機制沒壞，壞的是「使用者看得到的顯示層」和「規格敘述層」**。

  1. **cache-busting**：`extra.css?v=4.20.2`、`extra.js?v=4.20.2`——**規則 1 版號位置表 +2 處、升版 sed 納入**（`s/?v=OLD/?v=NEW/g`）。**從此部署新版，瀏覽器強制抓新 JS，版號即時跟上**
  2. **敘述層全修**：README 5 鈕清單、**「17 份 MD」改為不寫死數量**（審稿判準：「**會過期的確切數量不要寫進規格敘述**」——這是坑 #46「歷史註解不寫死版本號」的**數量版**）、CLAUDE.md 檔案摘要
  3. **check_js_runtime v2 補 active-state 斷言**（4 路徑）——**第一跑就抓到一個潛伏 bug**：首頁 match regex `^\/[^\/]*\/?$` 會匹配**所有單層路徑**（從 V3.4.4 就在猜層數）→ 改 **root 等值比較**；接著又暴露 **getSiteRoot() 的部署形態假設**（第一層=repo，根部署會誤判）→ **測試路徑改 project-pages 形態並把假設寫進註解**。**一道新測試連環抓出兩個潛伏問題**（Kit #78「工具死角」的正向實證）
- **可推廣的判準**：
  - 🔑 **「版號沒跟上」要分層診斷**：內部同步（機制）／顯示（快取）／敘述（規格文字）——**機制沒壞不代表使用者看到的是對的**。UI 上的版號經過「同步 → 部署 → 快取 → JS 執行」四關，**每一關都可能讓它過期**
  - 🔑 **由 JS 動態渲染的版本資訊，必有 cache-busting**——否則版號的「新鮮度」取決於瀏覽器快取，等於沒有
  - 🔑 **規格敘述裡不寫會過期的確切數量**（檔數、鈕數清單）——寫「原則」不寫「快照」；要寫數量就要有守門員盯（如 MIN_TRACKED）
  - **半吊子 replace 是敘述層腐爛的來源**：改一句話要讀完整句，**只 patch 開頭 = 製造新舊混血的句子**，比不改更誤導

**#79（V4.21.1）`markdown` 屬性把 flex 容器的子項包成一個 `<p>`——首頁階段條豎排錯亂，五道測試全綠**

- **症狀**：Sela 截圖首頁「你現在在哪個階段？」五個階段鈕擠成一直條、框線斷成括號狀；同頁「我現在要做什麼？」任務鈕、hub_learning 階段條同病
- **原因**：`<div class="home-stages" markdown>` 開了 md_in_html，Markdown 把連續幾行 `<a>` 視為一個段落包進 `<p>`→容器的 flex/grid 只對單一 `<p>` 生效，`<a>` 變行內元素，`<small>{display:block}` 把行內框拆行。**strict、anchor、元資料、JS 執行期五道測試都不看版面**——又一個 Kit #78 死角
- **做法**：(1) 純 HTML 內容的版面容器**不加 `markdown` 屬性** (2) CSS 防呆 `> p { display: contents }` (3) 掃描法：`grep -rPzo '<div class="[^"]+">\n<p><(a|span|div) class=' site` 找「容器第一個子項是 p 包住帶 class 元素」 (4) 版面改動用 Playwright 對元素截圖驗收（桌機＋手機寬度）

**#80（V5.3.0）模板用 `{{ base_url }}/路徑` 在 404 頁產生雙斜線——新的全站連結檢查第一次跑就抓到**

- **症狀**：`check_site_links()` 上線第一跑，404.html 的底部導覽、麵包屑全部是 `/CCM-manual//hub_daily/` 這種雙斜線網址
- **原因**：一般頁面的 `base_url` 是相對路徑（`..`），404 頁是絕對路徑且結尾已有斜線（`/CCM-manual/`），模板再自己加 `/` 就重複。瀏覽器多半照樣能開，所以從 V5.0.0 起沒人發現；舊的 `check_anchors.py` 只看 `../頁/#anchor` 一種寫法，看不到模板產生的連結
- **做法**：模板一律用 mkdocs 的 `url` filter（`{{ "hub_daily/" | url }}`、首頁用 `{{ nav.homepage.url | url }}`），不要自己拼 `base_url`。連結檢查要掃**產物**而不是原始碼——模板、raw HTML、教材產生的連結只有在產物裡看得到

**#81（V5.5.0）深色模式的主色被 Material 蓋掉——`:root` 覆蓋變數只在淺色模式有效**

- **症狀**：深色模式下 header 是 Material 預設的靛藍、表格表頭是 #eef2f5 淺灰（在深色背景上刺眼）、品牌色文字在深灰底上幾乎看不見
- **原因**：規則 7 的覆蓋寫在 `:root, [data-md-color-scheme="default"]`。Material 把 `--md-primary-fg-color` 設在 `body[data-md-color-primary=indigo]`，body 比 :root 近，淺色模式靠第二個選擇器（同樣掛在 body、且 extra.css 較晚載入）才蓋得過；深色模式 body 是 `slate`，第二個選擇器不成立，於是主色回到 indigo。表頭與審閱列的顏色則是寫死的淺色色碼，沒有深色版本
- **做法**：主色覆蓋改寫 `:root, [data-md-color-primary]`；其餘顏色集中成 `--ccm-*` token，淺色／深色各一組；品牌色當「文字／邊線」時用 `--ccm-ink`（深色模式換亮色），當「背景」時才用主色。hook 擋 token 區以外的寫死色碼。改樣式後要截深色模式的圖
